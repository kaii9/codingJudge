# 5. 面试表达、追问与简历边界

## 5.1 一分钟介绍（可按自己的表达调整）

我用 Go 做了在线代码评测系统，支持题库、登录、多语言提交、判题历史和排行榜。我重点做的是异步判题可靠性和真实的服务边界：平台管理用户与题库，Judge 管提交和结果，Executor 独立执行不可信代码，Web 和 Worker 不持有 Docker Socket。

内部链路使用版本化 gRPC；创建和完成各有事务 Outbox，通过 Redis Streams 投递。Worker 用数据库租约、随机所有权 token 和有界 attempt 防止旧结果覆盖新结果；平台消费完成事件维护幂等排行榜投影。验证包括真实 RPC、数据库权限、浏览器 E2E、在途 Executor 崩溃及强制退出恢复。双 Executor 目前共享本机 Docker daemon，因此我只声称进程级故障恢复和独立部署，不夸大跨主机 HA。

## 5.2 三分钟 / 五分钟结构

三分钟：业务背景20s → 为什么拆40s → 创建/执行/结果事件链60s → 一个失败窗口40s → 验证与限制20s。重点不是把所有技术名词挨个念出来，而是说明一个设计如何保护一个不变量。

五分钟再加：数据归属、题目快照、健康选择与 Admission、deadline/恢复预算、追踪定位例子。被打断时先回答问题，不坚持背完整稿。

## 5.4 高频问题：回答 + 追问准备

### 1. 为什么不是一个进程？

因为 Web 公网权限与 Docker 执行权限不应混在一起，执行资源和 HTTP 扩容也不同。代价是 RPC失败、配置和部署复杂度；所以只围绕真实边界拆，没有把每个工具做一个微服务。追问：为什么 Judge API 和 Worker 仍共享库？同一个判题领域，不是两个独立领域争夺数据。

### 2. 分库是不是分布式事务？

不是。各领域使用本地事务，跨域靠完成事件和投影最终一致。不对平台用户表和 Judge提交表做跨库 JOIN / 外键。追问：用户删除导致 Judge 悬空 ID 怎么办？当前没有完整删除/补偿流程，未来需领域事件和保留策略。

### 3. 为什么提交时带题目快照？

否则等待队列期间题目变更会改变已经受理的评测规则。快照与提交同事务保存，幂等重放沿用第一次快照。追问：对象文件后来被改怎么办？metadata 的 size/SHA校验发现变化，但还需要不可变 object key / 对象版本策略；不是仅靠 JSON 快照就保证所有文件不可变。

### 4. 服务 token 有了还为什么检查 user ID？

token证明调用者被允许访问内部服务，不证明用户可读某份提交。Judge按 user+submission约束资源。追问：恶意内部平台能伪造 user ID 吗？目前平台是受信调用者，可以代表用户；尚未实现终端用户签名身份或细粒度服务权限矩阵。

### 5. Outbox 能保证消息只发一次吗？

不能。XADD 成功但标 published 失败会重发。它保证发布意图不因本地 commit 后崩溃丢失，消费者仍要幂等。追问：Redis整库丢失怎么办？已published记录不会自动全量重发，需要灾备/对账设计，当前不能说已验证零丢失。

### 6. 为什么 Streams 已有消费者归属还要租约？

队列归属只控制消息投递，不约束数据库迟到写入。数据库 token+lease才约束最终结果，且租约覆盖对象拉取与持久化，不只代码运行。

### 7. fencing token 是否单调？

本项目随机 token 是数据库 CAS 所有权版本，不是单调递增序号。旧 token不能更新结果，不能直接拿去让第三方存储比较大小。追问：旧Docker执行会不会继续？短时间可能，所以不承诺物理执行 exactly-once。

### 8. 执行完成响应丢失怎么办？

一次 RPC 不配置执行级重放；Worker按预算开新 attempt，可能重复执行，结果只能由当前 token提交。Execution ID只做关联，不是去重缓存。用 `TestGRPCLostResponseDoesNotReplaySuccessfulExecution` 解释具体覆盖范围。

### 9. deadline 与取消区别？

deadline是最晚结束时间，cancel是主动终止信号。子任务不能超出父预算；服务关闭取消根Context；异步Worker只继承已持久化trace，不继承浏览器已结束的请求Context。

### 10. 任务已经超时，还能写重试状态吗？

不能继续用过期taskContext。当前从仍存活的父Context派生5秒收尾预算，且还要有效token/lease。根Context取消时不脱离后台写。超过实际执行预算的崩溃接管只终结，不再执行。

### 11. 怎么控制重试风暴？

限制Worker attempt、Executor槽位/等待者、RPC deadline，Outbox退避上限30秒，区分永久错误与可恢复错误。不是所有错误立刻打三次RPC。追问：有没有全局共享重试预算/熔断器？尚未实现，当前是任务级预算与背压，不冒称完整服务网格治理。

### 12. round_robin 等于高可用吗？

只在可用连接之间选择，health watch能排除NOT_SERVING。端点配置是静态的；两实例共享daemon时，daemon/宿主失效会一起受影响。当前证明进程恢复，不是物理HA。

### 13. drain 为什么不直接 kill？

先NOT_SERVING避免新工作，再等在途，宽限到期取消并清容器。既保护业务也避免无限退出。强制退出后Worker恢复任务。追问：健康探针能把drain实例变回SERVING吗？测试明确禁止这类“复活”。

### 14. 重启怎么避免误删别人的沙箱？

容器名称前缀与稳定唯一的executor owner标签共同约束清理范围。不同活跃实例不能复用同一ID。追问：所有孤儿对象也清了吗？没有，MinIO orphan object GC另需设计。

### 15. 排行榜为什么不用查Judge库？

跨域直查破坏数据所有权，并让每次排行依赖Judge可用性。平台维护本地投影，允许短暂延迟，event_id去重+version防迟到。提交详情直接读权威Judge，因此可能先看到AC，稍后榜单才变化。

### 16. Projection commit成功、ACK失败会重复加分吗？

不会按消息直接累加；processed event和projection同事务，再次收到会去重，排行按projection聚合。重复AC计accepted submissions，但distinct problem只解一道。

### 17. 兼容测试是不是测两份Go结构体？

不是只有编解码比较。冻结旧proto生成客户端，向当前实际gRPC服务器发请求，检查响应和Runner执行。它只覆盖该fixture与语义，不保证任意未来发布。

### 18. E2E和集成测试区别？

集成验证真实组件协议/事务，E2E从浏览器用户动作覆盖整条链。浏览器trace是测试重放，OTEL trace是跨服务因果链，不能混为一谈。两个按viewport互斥的skip要报告为skip。

### 19. Docker为什么不算强安全边界？

共享宿主内核与Docker管理权限存在攻击面；当前有资源/网络/文件/权限限制，但不是完整多租户安全平台。生产还需更强sandbox、镜像漏洞治理、主机隔离和审计。运行包装器与用户程序权限不同，编译阶段也不能概括为全部非root。

### 20. 追踪能定位什么，不能定位什么？

能关联HTTP→Judge RPC→异步Worker attempt→Executor RPC，并区分实例和失败attempt；看RPC耗时与attempt间隔。当前没有完整SQL/Docker内部span，SIGKILL可能丢失未flush span，不能仅靠trace证明数据正确性。

### 21. CI红了，你会怎么解释？

先给版本/日志证据，定位镜像来源或依赖漏洞；修可修复项，保留门槛并明确剩余阻断。不能通过删除audit、降级不匹配插件或把dev依赖排除来声称安全完成。本次未修复braces就是一个真实案例。

### 22. 项目最难的部分是什么？

选一个自己能复现的难点：例如执行预算耗尽仍需fenced收尾，或长任务artifact落库时租约也不能过期。按“原缺陷→测试如何失败→最小修复→复验→剩余边界”讲，不只说“用了Redis提升并发”。

### 23. 为什么不立即加注册中心、网关、Service Mesh？

当前最小固定拓扑已能说明边界、调用治理和独立部署。新组件需对应真实规模/运维需求，否则增加故障点却没有可验证收益。未来优先跨主机部署与恢复、协议演进流程、事件对账和安全依赖治理。

### 24. 性能提升数字怎么回答？

历史固定负载实验在报告指定环境比较Worker数量，不等于生产峰值。HTTP rate含轮询，不能当作提交QPS。新微服务拆分主要目标是权限、所有权和治理，不承诺必然更快；需重新做同负载基线对照才可比较。
